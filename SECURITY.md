# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public Issues, Discussions or pull requests.

Use the repository’s **Security** tab and GitHub private vulnerability reporting when it is available. If private reporting is not yet enabled, contact a repository maintainer privately through GitHub and ask for a secure reporting channel without including exploit details.

Include only what is necessary:

- the affected specification, implementation or component;
- the impact and realistic attack conditions;
- steps to reproduce or a proof of concept;
- suggested mitigations, if known; and
- whether the report involves personal, credential or sovereign data.

Maintainers will acknowledge a valid secure report, coordinate investigation and remediation, and publish an advisory when disclosure is safe. Response times will be formalized as the security team grows.

## Scope

This repository currently contains standards work. Reference implementations and deployed M5 services may have separate security policies and reporting channels. A specification concern that could create unsafe implementations is in scope here.

Never include live credentials, private keys, personal records, confidential government information or protected community data in a report.
