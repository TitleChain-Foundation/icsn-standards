# Contributing to ICSN Standards

Thank you for helping build open, human-rooted standards for identity and sovereign networks.

## Choose the right pathway

- **Questions, introductions and early ideas:** use [Discussions](https://github.com/TitleChain-Foundation/icsn-standards/discussions).
- **Specification defects or clearly actionable work:** open an Issue.
- **Proposed standards changes:** open an RFC pull request.
- **Security vulnerabilities:** report them privately as described in [SECURITY.md](SECURITY.md).

## RFC process

1. Start a Discussion to test the problem and gather stakeholders.
2. Create an RFC from the template in rfcs/0000-template.md.
3. Give the RFC a descriptive filename such as rfcs/0001-human-rooted-identifier.md.
4. Open a pull request and explain the problem, affected communities, privacy and security implications, interoperability impact, and implementation considerations.
5. Address public review before the RFC advances.

RFC stages are **Draft**, **Candidate**, **Stable**, and **Deprecated**. A proposal is not a Foundation standard merely because it appears in this repository.

## Contribution principles

Contributions should be:

- human-rooted and rights-respecting;
- implementation-neutral where possible;
- explicit about trust, consent, privacy and governance;
- usable by sole proprietors, startups, cooperatives, institutions, governments and sovereign nation states;
- accessible to communities with different technical and economic resources; and
- testable through examples, reference implementations or conformance criteria.

By participating, you agree to follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Governance decisions follow [GOVERNANCE.md](GOVERNANCE.md).

## Licensing

Do not contribute material you do not have the right to submit. A repository license and contribution terms will be adopted before any specification is declared Stable.
